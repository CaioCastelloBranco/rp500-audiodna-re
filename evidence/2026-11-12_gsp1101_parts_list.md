# GSP1101 parts list — the two AudioDNA2 chips are the *same* ASIC as the RP500's

**Date:** 2026-11-12
**Source:** `03_docs/GSP1101 parts list.docx` — "GSP1101 part list",
"08/31/2007 Dynamic List Display 1", Material `GSP1101`, description
`RACK GUITAR PRE AMP`. Extracted with `04_analysis_scripts/docx_text.py` to
`05_evidence/gsp1101_parts_list.txt`.

---

## 1. The DSP line (verbatim)

```
|....4|0990|72-1002 |B | 2 |IC Audio DNA2 Rev B ASIC 144 pin LQFP CB|BC|
```

- **Quantity 2** — two AudioDNA2 ASICs.
- **Harman part `72-1002`** — the *same base part number* the RP500 carries
  on U25, whose marking reads `72-1002 GREEN / 7169170 / 1012 KOREA`
  (`05_evidence/board/02_dsp_audioDNA2_sdram_flash.jpg`).
- "Rev B" is the GSP build; the RP500's "GREEN" is a finish/RoHS-style suffix,
  not a different part number. *(Whether "GREEN" is a later silicon revision is
  the one remaining marking-level caveat; the part family is identical.)*

## 1b. The AudioDNA family across the sibling service manuals

The newly added service manuals/schematics give the part-number lineage:

| Product | DSP part | Qty | Description |
|---|---|---|---|
| GSP 2101 (1993) | `72-3172` | 1 | "ASIC, Digitech Custom DSP" — pre-AudioDNA |
| GSP 2112 (1998) | `72-3042` TMS57070 + `72-3181` SDISC3181 | 1 + 2 | pre-AudioDNA |
| GNX 2 | **`72-5433`** | **3** | "IC AUDIO DNA ATMEL QFP-144" |
| RP50 | **`72-5433`** | **1** | "IC AUDIO DNA ATMEL QFP-144" |
| **GSP1101** | **`72-1002`** | **2** | "IC Audio DNA2 Rev B ASIC 144 pin LQFP" |
| **RP500** | **`72-1002`** | **1** | marked `72-1002 GREEN` |

Two things fall out:

- `72-5433` is the **first-generation AudioDNA** (Atmel, QFP-144); `72-1002`
  is the **AudioDNA2** (Rev B, 144-pin LQFP). The GSP1101 and RP500 are both
  AudioDNA2.
- The **DSP count scales with the product tier**: RP50 = 1, GNX 2 = 3,
  RP500 = 1, GSP1101 = 2. The count is a capacity choice, not a feature flag.
  The GSP1101's second chip is not a special "convolution chip"; it is a second
  copy of the same ASIC.

## 2. Each DSP has its own SDRAM

```
|....4|0940|72-0099 | | 2 |IC 64MBIT SDRAM 4Mbx16 7.5nS TSOP-54 |AB|
```

Two 64 Mbit SDRAMs — one per AudioDNA2. The RP500 board has **one** SDRAM
(U24, Samsung `K4S641632N-LC75`, 64 Mbit). So the GSP is **two complete
DSP + SDRAM subsystems**, the RP500 is **one**.

## 3. The rest of the DSP-era logic

| Qty | Part | Description |
|---|---|---|
| 1 | `72-0071` | TAS1020B USB controller |
| 1 | `72-0089-06V1|20` | 16 Mbit 3.3 V flash, "GSP1101 OS" |
| 1 | `72-0157` | CS42426 codec, 2 in / 6 out, 114 dB, LQFP64 |
| 1 | `72-0240` | AK4556 codec, 24-bit 192 kHz |
| 1 | `72-0175-00V1|00` | **CPLD EPM3032A TQFP44** |
| 1 | `72-6318` | SRAM AS7C3256 32K×8-15 ns |
| 3 | `72-0020` | 74LCX244 buffer/line driver |
| 3 | `72-1263` | 74HC574 octal D flip-flop |
| 2 | `72-1452` | 74AC138 1-of-8 decoder |
| 1 | `72-5437` | 74HC273 octal D flip-flop |

The **EPM3032A CPLD** is the obvious candidate for the address decode / chip
select that maps two DSPs (and two SDRAMs) into the 8051's 64 KB XDATA window.
That is why the firmware never emits an explicit DSP-id byte: the board's CPLD
does the demultiplexing. The RP500, with one DSP and one SDRAM, needs less of
that logic.

## 4. What this settles

| Question | Answer |
|---|---|
| Are the GSP's two chips a *different* AudioDNA2 variant from the RP500's? | **No — same base part `72-1002`.** The "only one chip, unique to this product, has convolution instructions" hypothesis is **refuted at the part-number level**. |
| Are the GSP's two chips different *from each other*? | **No — the BOM specifies qty 2 of the same `72-1002` Rev B.** They cannot differ in instruction set, so "only one of the two GSP chips convolves" is also refuted at the part-number level. |
| Is the RP500's single chip the same silicon family as the GSP's? | **Yes.** Same `72-1002` AudioDNA2 ASIC. |
| Why does the GSP have two? | **Capacity / partitioning**, not a different instruction set: two DSP + two SDRAM subsystems. |
| Does the RP500's chip therefore have the convolution hardware? | **The ASIC is the same part**, so the *capability* is a microcode/firmware question, not a chip-identity question. |

## 5. What it does **not** settle

- The DSP **microcode** is still not in any artifact. The same ASIC can run
  different microcode, and the firmware image does not contain (or clearly
  load) a convolution program.
- Whether the CPLD routes `0xD070` to one DSP, both, or a selected one is not
  in the BOM; it is in the schematic/CPLD netlist, not yet available.
- Whether the RP500's `72-1002 GREEN` is the same silicon revision as the GSP's
  `72-1002 Rev B`. The part number is the same; a revision difference would not
  normally *remove* a DSP instruction.

## 6. Consequence for the port

The gate is now narrower and purely **firmware/microcode**:

1. The RP500's ASIC is the same `72-1002` as both GSP chips — so the earlier
   worry that the RP500 might carry a *different, convolution-less* chip is
   gone.
2. The remaining question is whether the RP500's DSP can be put into the
   variable-length block mode the GSP uses, and whether it convolves with it.
   That still needs a bus capture or the DSP microcode — but it is no longer a
   two-chip / chip-variant question.

The correct statement remains: **"not demonstrated", not "impossible."** The
parts list removes one of the two hardware doubts (chip identity); the
microcode doubt remains.
